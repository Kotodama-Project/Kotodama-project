# 無料Lumaとn8n

この連携は任意です。Lumaを使わない個人・コミュニティも、Discord本体を単体で使えます。

LumaのイベントはLumaが管理し、Kotodamaは準備・確認・成果の仕事を管理します。無料構成ではLuma API、Webhook、Zapierを前提にしません。

管理画面には普段使っているブラウザのログイン済みセッションを使います。Googleログインが専用ブラウザで「安全でない可能性があります」と拒否された場合は、同じログインを繰り返しません。[既存セッションでの分担と任意のCLI接続](BROWSER.md)へ切り替えます。ログインが切れている場合は本人が認証します。エージェントが接続する経路では、完了後のアカウントとイベント管理権限を読み戻します。公開ページを読めることと管理画面を編集できることは別です。

ブラウザ全体の操作権限は必須ではありません。その接続を選ばない場合は、本人が普段のブラウザで管理画面の編集とCSV出力を行い、エージェントは渡されたCSVからCLI処理を再開します。管理画面へ接続できていなければ、変更保存の自動確認は未実施と記録します。

1. CLIからイベントの現在の内容を読む。
2. Discordで募集原稿・更新案・当日資料を依頼する。
3. 許可済みの編集内容をLumaへ反映し、画面で読み戻す。
4. Luma管理画面から取得したCSVを取り込む。CSV取得時刻以降の申込変更は含まれません。
5. 参加状況・準備タスク・案内下書き・振り返りをDiscordの仕事へ戻す。

`integrations.luma.eventUrl`と`eventRef`に自分のイベントを設定します。申込者の連絡先やQRコードをLLM・Discordへ渡さず、件数・状態と不可逆な識別子で整理します。参加者の同じ名前や複数チケットを単純に一人ずつ数えません。

## n8n

`examples/n8n/luma-import.json`は手動起動の取込フローです。実ID、認証情報、送信先を含みません。n8nのCredentialとprivateな接続URLを設定してから利用してください。

テンプレート側の `bridge.enabled`、`bridge.actorId`、`KOTODAMA_BRIDGE_TOKEN`、対象イベントを設定します。bridgeはloopbackへだけbindします。別ホストのn8nは、管理者が既存のprivate接続を使ってこのloopbackへ到達させます。外部公開の無認証Webhookにはしません。

`POST /v1/luma/import`には`eventRef`、CSV文字列`csv`、取得時刻に対応する数値`revision`を渡します。認証されたbridgeの設定済みactorだけを使い、payloadから操作者や実行権限を受け取りません。取込から自動的に開発や参加者配信を始めません。

Botが起動している場合、取込結果は `bridge.actorId` 本人のDiscord DMへ通知します。送信直前に現在の操作者設定、サーバー所属、出典と結果チャンネルの閲覧権限を確認し、保存済みの出典から取込行数・識別できた参加者数・チケット数だけを作ります。他の操作者や共用チャンネルへは送りません。これはCSVの取込結果であり、仕事の完了通知ではありません。Bot tokenはBotの実行ホストに保持し、n8nにはbridge用Credentialだけを設定します。

同じイベント・CSV内容・本人への通知は一度だけです。CLIで先に取り込んだCSVでも、本人へ未通知なら最初のbridge経由の重複取込で通知できます。配送結果不明の通知を自動再送せず、出典の撤回や版・操作者の不一致があれば送信しません。音声の停止やAPI残高不足、仕事の停止設定は変更しません。

HTTP応答の `state` は取込結果、`notification.state` は通知結果です。通知の失敗で取込成功を失敗へ変更しません。

| notification.state | 意味 |
|---|---|
| `sent` | 本人DMの送信結果を確認 |
| `already_sent` | 同じ取込結果を通知済み |
| `unknown` | 配送結果不明。重複を避けるため再送しない |
| `blocked` | 現在の出典・操作者・閲覧権限を確認できず未送信 |
| `unavailable` / `not_configured` | 通知経路を利用できない、または未設定 |

iCalは日程情報の取込に使えます。参加者・申込情報をiCalから取得したとは扱いません。
