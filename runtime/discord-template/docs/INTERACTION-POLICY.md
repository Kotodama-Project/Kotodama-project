# 不足情報を一度だけ確認する

#145のowner採用案Cを実装しています。analyzerは最大300文字の質問候補とintentの位置を
`clarification`へ返し、runtimeが送るかどうかを決めます。既定`once`、設定で`off`を選べます。
明示・完全なrequestだけが従来のTask admissionへ進み、現在のaction grantを確認します。
確認への回答、引用、呼びかけだけ、雑談、不明話者から権限を作りません。

## 単位と経路

同じprovider / guild / channel / actorに開く確認は一つです。operatorが話しかけ、
許可済みactionの明示requestが不完全で、返答経路があるときだけ質問候補を使います。
一つの発言で複数候補があっても一通までです。完全な依頼からTaskを作った発言では、
追加の質問を重ねず、不完全な残りを候補に保ちます。

テキストは本人へのDMです。DMを取り込む経路はないため、元チャンネルへBotをメンションして
答える案内を必ず添えます。チャンネルへの質問の公開や、応答がない場合の別経路への転送はしません。
音声は既存assistのcommentary返答を使い、現在の聴衆が出典を読めるかを再確認します。
minutes、自然会話、native会話、stop/end actionと重なる場合は確認しません。

## 一度という制限と記録

既存SQLiteのeventsへ`interaction.decision`と`interaction.clarification_asked` / `_closed`
を残します。eventには部屋・actor・出典/intent参照・時刻・状態だけを書き、質問本文は書きません。
質問文は元のintentsの同じ版に保持し、本人と全出典の現在のread範囲・版を照合して読みます。
新しいTask表や確認から依頼を自動合成する台帳は作りません。

送信前にtransactionで一回を予約します。送信結果が不明でも自動再送しません。
再起動後も同じ記録を使い、別の話者・部屋へ質問を渡しません。本人の次の出典にだけ
`PENDING_CLARIFICATION`として質問と参照を渡し、再解析します。これは未信頼の資料であり、
原文や現在のgrantの代わりではありません。元の出典の訂正・撤回・閲覧取消後は渡しません。

次の出典を解析するとpendingをansweredへ閉じます。その答えが不十分なら、同じ窓内の
断片にも二度目は問いません。この抑止はTask作成・音声会話終了・期限切れで解除されます。
期限は既定600秒、最大3600秒です。音声session終了後の遅延入力は同じsessionで再質問せず、
別の新しいsessionは改めて判定します。質問候補を通常replyへ入れて回数制限を避けることも
抑止します。固定の質問儀式や、工程ごとの再承認は増やしません。

確認送信中の権限変更や出典撤回は、送信直前と音声聴衆の再検査で停止します。
合成試験は構造化候補、永続化・重複・並行性・取消・再起動を検証します。
自然言語の意味理解、質問の有用性、実Discord・実VC・実APIの受入は#154 / #156に残ります。
