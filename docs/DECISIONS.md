# 方針の決定

## 2026-10-21 — OpenAIフルスタックへ縮小

所有者は、OpenAIの既存技術で可能な限り置き換え、不要物を消し、古い機能を誤って使わない構成を求めました。この要求が、以前のCompany OS・汎用agent基盤の実装方針を置き換えます。

本来ほしい成果は、会話から目的を理解し、訂正を保ち、仕事を終わらせ、検証した成果へ戻れることです。独自の実行基盤やデータ形式の維持は、その成果そのものではありません。

### 採用する状態

- 対話・計画・分担・実装・再開・検証はCodex。継続する責務は必要なときだけOpenAIの既存機能へ渡す。
- 仕事の原意・制約・訂正・採否・成果は、対象repoの短い文書、Issue、PR、CIへ残す。同じ内容を言霊へ再登録しない。
- memoryは背景を思い出す補助。実行権限、正本の変更、共有許可は元資料と現在の許可に従う。
- 接続は既存pluginを優先。不足が再現されるまで独自API wrapperも作らない。

### 終了する開発

Company OS、独自Task/Project状態、swarm・scheduler・再計画loop、知識検索/OKF/Context Platform、Company Packの審査runtime、独自GUI、配備profile、Discord/Luma専用bridgeをactive sourceから除去します。過去のテストや候補設計はGit履歴に保全し、今後の必須要件にはしません。

### 引き継ぐ責任

原意と訂正を失わないこと、成果を確認すること、秘密情報と既存データを守ることは継続します。旧稼働環境を新mainへ直接更新しません。保存データ・鍵・consumerの移行は[別の手順](RETIREMENT.md)で扱います。

OpenAIへの移行は旧local-first・ACL・保持・可搬性保証を自動継承しません。業務データはアクセス可能だからという理由だけで別サービスへアップロードしません。

### 判断を変える条件

実際の仕事で、既存OpenAI製品では満たせない要求が再現され、追加する仕組みが増やす手間より明確な利点がある場合だけ再検討します。旧コードが存在すること、以前のIssueが未完であることは再開理由にしません。
